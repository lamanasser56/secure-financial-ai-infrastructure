# Claims matrix (Phase E agent platform)

A claim is **live-tested** only after the full live chain has passed and the evidence file is committed. Until then
it is **designed** (implemented, with offline or plan-level checks only). This file is the platform's claims matrix.

| Claim | Status | Evidence |
|---|---|---|
| No internet egress: no Cloud NAT, no external IPs; Google APIs via Private Google Access, and the two `rep.googleapis.com` endpoints (Vertex AI `us`, Sensitive Data Protection `us-east1`) via Private Service Connect regional endpoints with private DNS zones | **live-tested** (2026-10-11) | `platform/clouds/gke/terraform/module/private_endpoints.tf`; Terraform apply 8/8 and re-plan 0 changes (2026-10-10); `docs/evidence/requalification.json` PASSED: every model and redaction call of the live chain went through these private endpoints, and the cluster has no NAT. |
| The Ops Agent cannot change what a registered workload runs, even with a compromised identity: only rollout restart (template changed by the restart annotation only) and bounded scale; no rollback, no image, command, args, env, envFrom, resources, probe or label change. For OOM, image-pull and admission-denied findings the agent diagnoses, explains and recommends an owner action (shown in the UI as "Owner action required — no automated fix"); it never fixes them itself | **live-tested in part** (run 6, 2026-10-19: RBAC `can-i`, `OBJECT_CHANGED`, verified restart) + admission template denials on a real kube-apiserver (envtest, 15 cases) | `platform/core/kubernetes/policies/admission.yaml`; `make test-policies` on a real kube-apiserver denies 15 template changes made as the ops-agent identity (2026-10-11). Live: `docs/evidence/attack-suite.json` (run 6: `ops_agent_cannot_change_onboarded_agents`, `ops_stale_approval_refused` with its verified restart); the live suite does not attempt a template change as the ops-agent identity. The former rollback branch did not compare command/args/env/envFrom/resources/probes/workingDir/lifecycle/labels: found by an independent AI review (Claude) of `admission.yaml`; the owner decided the fix (remove rollback) and required envtest proof before merge. |

## Recorded limitations

| Limitation | Effect | Where it is recorded |
|---|---|---|
| **Person names are not redacted.** The qualified redaction entity set (Sensitive Data Protection context + the deterministic email layer) covers card numbers, email, IBAN, phone and Saudi account/ID/VAT numbers, and has no person-name (PERSON) category. | A name typed into a question reaches the model provider as written. The covered entities are masked before the provider. The requalification redaction case (5a) therefore tests email + phone only, and no claim covers names. | `docs/agent-platform/model-requalification.md` (case 5); `runtime/phase3/trusted_runtime.py` (`SUPPORTED_ENTITIES`) |
