## Egress alternatives and recommendation

Read-only inspection found Calico NetworkPolicy, omitted/default legacy datapath fields, no enabled FQDN flag or FQDNNetworkPolicy CRD, NodeLocal DNS and policies confined to the existing application namespace. The existing cluster cannot use native FQDN policies. No in-place conversion, replacement, policy change or resizing of MASAR is proposed.

| Criterion | Dedicated Dataplane V2 cluster: recommended | Narrow gRPC CONNECT proxy/gateway |
| --- | --- | --- |
| Enforcement | Native DNS-derived IP/port allowlist; remove additive broad HTTPS; shared-IP limitation remains. | Pod policy allows only proxy plus DNS/metadata; proxy must deny direct-IP CONNECT and all unapproved hosts. |
| SDK/authentication | Existing gRPC transport, TLS validation and GKE metadata identity remain unchanged. | gRPC Core supports `grpc_proxy` HTTP CONNECT; metadata must bypass it through a separate scoped path. Must qualify the actual locked Python transport with the selected gateway. |
| Resources/cost | Nine declared resources, one node, NAT/address, disk and control plane; bounded lifetime. | Existing cluster can be used, but a new proxy Pod/image needs maintenance and qualification. Managed Secure Web Proxy needs gateway, policy/rules, proxy subnet and APIs. |
| Qualification | No new runtime image. Offline contracts plus runtime allow/deny evidence on the new cluster. | A new image needs deterministic build, SBOM and unchanged vulnerability qualification; a managed gateway still needs transport/policy qualification. |
| Reuse/cleanup | Source supports later infrastructure tests; remove compute/network and disable node identity after this run. | Self-hosted proxy source can be reused; policy, patching and TLS/CONNECT failure behavior need ongoing ownership. |
| Portability | FQDNNetworkPolicy and GKE metadata are Google-specific; the core harness/result contract remains portable. | CONNECT is more portable, but gateway management and cloud metadata paths remain provider-specific. |

The dedicated [cluster root](../../infra/gcp/google-sdp-evaluation-cluster/README.md) is selected. It avoids an unqualified proxy image and avoids altering the existing cluster. This is a network boundary, with the shared-IP and DNS limitations below; it is not complete hostname isolation. A proxy would not be substituted automatically if native qualification fails. The [gRPC proxy path](https://grpc.github.io/grpc/core/md_doc_core_default_http_proxy_mapper.html) is documented, but no proxy has been demonstrated or approved. Managed [Secure Web Proxy](https://cloud.google.com/secure-web-proxy/pricing) lists USD 1.25/hour plus USD 0.0193/GiB, before adjacent resources; its higher bounded cost and qualification work are not selected. No mesh, enterprise stack or TLS interception is proposed.

## Native boundary and verification

[GKE FQDN policies](https://docs.cloud.google.com/kubernetes-engine/docs/how-to/fqdn-network-policies) require Dataplane V2, supported GKE versions and cluster kube-dns or Cloud DNS. The selected root uses an available reviewed GKE 1.35 version and kube-dns without NodeLocal. The namespace has deny-all ingress; NetworkPolicy permits only cluster DNS TCP/UDP 53 and Dataplane V2 metadata `169.254.169.254:80`. Native FQDNNetworkPolicy allows only `dlp.me-central2.rep.googleapis.com` TCP 443. Both policies select every Pod in the dedicated namespace. The standard policy has **no public HTTPS rule**, wildcard destination or alternate metadata/DNS allowance. Unknown/missing native feature or CRD fails closed; there is no broad fallback.

Policies are additive: another matching NetworkPolicy or FQDN policy can broaden egress. Before preflight and immediately before unsuspending the live Job, inspect all namespace policies and any cluster-wide administrative/Cilium policies against the rendered set. Native policy uses cluster DNS responses and TTL to program destination IPs/ports. It performs **no Layer-7 hostname inspection**. Direct access to an allowed IP, or another Google API/hostname sharing that IP, cannot be distinguished. DNS query names themselves are not restricted, so this is not DNS exfiltration prevention. Application endpoint pinning and TLS hostname verification remain mandatory. DNS result/hostname quotas, CNAME behavior and conntrack retention apply. No claim of all-service IAM isolation follows from `serviceusage.services.use`.

The same verified image digest runs a separate 180-second, zero-retry [network probe](../../scripts/probe-google-sdp-egress.py), mounted as reviewed immutable ConfigMap code. It checks the runtime GSA email through metadata **without fetching a token**, verifies one TLS certificate/HTTP2 handshake to the approved SDP hostname **without a DLP API request**, and checks an unrelated hostname, its direct IPs, alternate HTTPS and alternate DNS routes. Up to three unrelated IPv4 addresses yield at most eight negative connection attempts, each limited to five seconds. Refused/reset/failed DNS, shared-IP negative targets, any successful unapproved connection or incomplete evidence fail qualification. There is no service fallback or proxy retry.

Timeouts alone are not policy proof. Enable [NetworkLogging](https://docs.cloud.google.com/kubernetes-engine/docs/how-to/network-policy-logging) only on the new cluster, delegated to annotated evaluation policies/namespace. The [offline evidence verifier](../../scripts/verify-google-sdp-egress-evidence.py) requires a genuine Cloud Logging allow event identifying the FQDN policy and matching deny events for every negative destination/port, same probe Pod, cluster and bounded time window. Retain the private log batch, sanitized observation JSON and verifier result. Probe JSON contains only test status, destination IP/ports, times and explicit limitations; no corpus, GSA email, project, token or response body. The operator must retrieve the genuine logs from Google, not fabricate fixtures. Missing verdicts block the live Job. Node routing/NAT readiness is also checked, so failed routing is not accepted as enforcement.

The live Job remains suspended until signature, identity, network and evidence gates pass. Apply controls and preflight first; collect/delete the preflight Job/Pod and ConfigMap before applying the suspended live Job. Quota remains one Pod and one Job. Unsuspend once after re-reading policies. The Job retains its 900-second deadline, zero backoff, restricted Pod Security, numeric UID/GID 65532, read-only root, dropped capabilities, seccomp and bounded resources. Metadata path tests do not prove successful DLP authentication; the subsequent bounded live harness provides that evidence separately.
