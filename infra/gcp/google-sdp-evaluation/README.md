# Terraform contract: synthetic Google SDP evaluation

This root module prepares Google Cloud identity and a dedicated Artifact Registry repository for the disabled, synthetic-text Google Sensitive Data Protection candidate. It does not create or modify a GKE cluster, Kubernetes ServiceAccount, GitHub variable, state bucket, workflow run, image, signing identity, or deployment. Microsoft Presidio remains authoritative. Only reviewed synthetic text is in scope.

The reviewed [release workflow](../../../.github/workflows/release-google-sdp-evaluation.yml) expects three GitHub environment variable names: `GOOGLE_SDP_RELEASE_WIF_PROVIDER`, `GOOGLE_SDP_RELEASE_SERVICE_ACCOUNT`, and `GOOGLE_SDP_RELEASE_PROJECT_ID`. This module outputs the matching provider name, release GSA email, and non-secret project ID contract; it does not set those variables. The `artifact_repository_id` must match the workflow dispatch input. The [GKE package](../../../kubernetes/apps/google-sdp-evaluation/README.md) renders the runtime GSA email as the dedicated KSA annotation only after a separate review. Its Job image still requires a signed `me-central2-docker.pkg.dev/...@sha256:` digest.

## Identity and permissions

The dedicated GitHub workload identity pool/provider accepts the exact repository, immutable numeric owner/repository IDs, `refs/heads/main`, a branch ref type, `workflow_dispatch`, and the exact release `workflow_ref`. These claims are documented by [GitHub](https://docs.github.com/en/actions/reference/security/oidc); Google documents [attribute mappings, conditions, and principal sets](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines). Verify the actual numeric GitHub IDs before supplying tfvars. A protected GitHub environment and explicit complete-bundle approval remain external prerequisites. The [proposed synthetic-only owner profile](../../../docs/security/google-sdp-synthetic-execution-proposal.md) permits owner approval only after its amendment is approved; it is not independent review, and separation of duties remains unproven. The provider additionally checks `assertion.sha` against the externally supplied `approved_source_commit`. The release GSA can be impersonated only by this provider's matching repository-ID principal set and has only repository-scoped `roles/artifactregistry.writer`. No key is created.

The runtime GSA is separate and receives no GitHub trust or registry role. The existing namespace and Kubernetes ServiceAccount are both `google-sdp-evaluation`. Its GKE impersonation member is `serviceAccount:${PROJECT_ID}.svc.id.goog[google-sdp-evaluation/google-sdp-evaluation]`, with the officially documented `roles/iam.workloadIdentityUser` service-account binding. The `gke_ksa_binding_identity` output resolves to that same member, and `ksa_annotation_value` supplies the existing renderer's GSA annotation input. The regional `projects.locations.content.inspect` and `projects.locations.content.deidentify` methods each document `serviceusage.services.use` as their required IAM permission; this module uses a one-permission custom role. Neither call uses KMS or templates. Verify current method permissions and the target project's billing/API status before any apply. No Vertex, LiteLLM, GCS, Secret Manager, KMS, Compute, Kubernetes API, or other-service-account permission is granted to the runtime GSA.

The module enables only Artifact Registry, DLP, IAM Credentials and STS APIs, with `disable_on_destroy = false` because project APIs are shared. Service Usage, IAM and Resource Manager APIs are external bootstrap prerequisites for Terraform and WIF provisioning; this module does not enable them. The operator must have narrowly scoped provisioning rights reviewed outside this module. An offline validation run must never become an API enablement or IAM mutation.

## Registry and retention

Kubelet pulls use the separately reviewed `node_service_account_email`, not the Pod's Workload Identity. The module grants this identity only `roles/artifactregistry.reader` on the evaluation repository; its access scopes must independently allow storage reads. Runtime and release GSAs are rejected as node identity inputs. This identity root changes no node, pool, cluster or existing workload. The selected [dedicated cluster root](../google-sdp-evaluation-cluster/README.md) supplies the new node identity; do not grant this reader binding to the existing MASAR node identity for the revised bundle.

The Docker repository is fixed to `me-central2`, enforces immutable tags, and grants no public access. An active cleanup policy deletes **untagged** versions older than 30 days; a keep policy preserves commit-tagged `sha-` releases. [Artifact Registry does not delete tagged artifacts when immutable tags are enabled](https://docs.cloud.google.com/artifact-registry/docs/repositories/cleanup-policy). Therefore signed release growth is not automatically capped. The operator must approve a release-count and storage-cost ceiling, monitor it, and obtain separate authorization for any retirement or repository replacement. Retain digest, scan, SBOM, signature and decision evidence under the separately approved evidence policy.

## Remote state bootstrap contract

The GCS backend intentionally commits only a prefix, never a bucket name. A separate, dedicated state bootstrap must create the bucket before real initialization. Require uniform bucket-level access, enforced public-access prevention, versioning, no website, no anonymous or `allUsers`/`allAuthenticatedUsers` binding, and reviewed retention/lifecycle protection for recovery. Use a separately approved bucket location and a dedicated operator identity with only state-object and lock operations on that bucket or prefix. Restrict state readers: Terraform state can contain resource identities and policy details even when outputs are non-sensitive. The [GCS backend supports locking and recommends object versioning](https://developer.hashicorp.com/terraform/language/backend/gcs).

Use `terraform init -backend=false` for offline validation only. **Never apply with local Terraform state.** Before a separately authorized real plan or apply, obtain the remote bucket name through an approved channel and initialize the GCS backend outside Git. Terraform may cache backend configuration in `.terraform/` and plan files; keep those out of Git and remove local copies after use. Do not commit credentials, project-specific tfvars, state, plans, or a backend bucket name. Do not create a state bucket in this root module.

## Location and authorization limit

The current GKE cluster is in `us-east1-b`, while the pinned Google SDP endpoint and Artifact Registry repository are in `me-central2`. This synthetic-text evaluation does **not** establish end-to-end Saudi residency. Production residency would require a separate Saudi-region compute, network, logs, storage, backup, and observability review. No real customer or financial data is authorized, and no result here permits Presidio deletion or provider cutover.

The GitHub provider also requires the default OIDC environment subject `repo:OWNER@OWNER_ID/REPOSITORY@REPOSITORY_ID:environment:google-sdp-evaluation-release`, with the fixed owner and repository substituted from validated inputs. Changing GitHub's subject customization requires a new trust review. Stage 1 inventory and the single execution-approval checkpoint are defined in the [milestone readiness record](../../../docs/security/google-sdp-milestone-readiness.md).

The legacy exact namespace/KSA member belongs to the project workload pool and does not distinguish clusters. Production isolation would need separate review. The dedicated cluster cleanup disables the retained node GSA and removes its project node-role binding; its inactive repository-reader grant and state remain retained for later reviewed reuse.
