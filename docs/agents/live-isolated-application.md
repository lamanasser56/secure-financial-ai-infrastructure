# Isolated Financial and Operations application

The application runs as UID 65532 in a read-only, network-none container. Its
peer-checked Unix channel reaches a trusted controller outside the container.
Only that controller holds database credentials, service recipes and durable
audit. Model requests use scoped LiteLLM clients and the pinned chat route.
The application has no Docker socket, cloud identity, host network or audit mount.
This boundary assumes a trusted controller, operator and worker kernel.

Local reasoning and redaction are explicitly simulated. Live admission requires
the unchanged 70 mandatory plus 16 observation campaign, exact provenance,
native network/client/quarantine evidence and accepted synthetic processing scope.
Historical 59 passes and context-060 failure remain unchanged. No fallback,
amount-field exemption, automatic campaign rerun or provider promotion is allowed.

## Separate admissions

`fixed_inputs_qualification` admits only the two current financial inputs, one
controlled test-service outage/restoration and two evidence explanations. The
financial inputs cannot be replayed or replaced with free text. The qualification
driver verifies grounded tool results, actual model responses, denial, restoration,
durable counters and unchanged credentials. Its PASS issues no free-text grant.

`supervised_synthetic_free_text` requires that fixed result and its own explicit
owner grant. It allows own Arabic/English wording over the approved synthetic
tenant and registered test services for fifteen minutes. Existing model, byte,
operation, conversation, audit, policy and approval limits remain enforced.
Recovery refreshes neither credentials nor budgets. No user stack is a write target.

## Local use

Use the committed source, current qualification record, required database archive
and newly qualified application/gateway archive on secure-infra-worker. Add
`--application-archive` to the existing recoverable launcher; this selects actual
container isolation. Start with a new private state and three unused loopback
ports. The owner checkpoint supplies exact commands and artifact hashes.

Financial: ask a question with a reporting month, or answer the period clarification.
Review the calculated total, ranked categories, period and source. Operations:
Observe, Diagnose and Propose a registered action. Review evidence and code policy;
enter the operator capability only in its password field, then approve/execute once.
Inspect VERIFIED or FAILED and the health proof. Monitoring survives model outage.

Stop using that source's `--stop --state` command. Retain private audit and use a
new state for a later explicit local launch. Production identity, remote immutable
audit, broad redaction accuracy and hostile-controller isolation are not qualified.
